# Sonic 애니메이션 뷰어 개발 PRD

## 1. 문서 정보

- 제품명: Sonic 애니메이션 뷰어
- 대상 경로: `Labs/LEC09`
- 구현 파일: `sonic_animation_viewer.py`
- 스프라이트 에셋: `sonic-sprite.png`
- 기술 스택: Python, pico2d
- 문서 상태: 개발 기준

## 2. 제품 개요

`sonic-sprite.png`에 포함된 Sonic의 모든 애니메이션 모션을 순서대로 보여주는 데스크톱 뷰어를 만든다. 각 모션을 5회 재생한 뒤 1초 동안 대기하고 다음 모션으로 넘어간다. 마지막 모션 뒤에도 1초 대기한 다음 첫 모션부터 순환 재생한다.

## 3. 목표와 범위

### 목표

- 스프라이트 시트의 캐릭터 모션을 잘라내어 실제 애니메이션처럼 재생한다.
- 프레임 원본 크기의 4배로 캐릭터를 표시한다.
- 정해진 모션 순서, 반복 횟수, 모션 간 대기 시간을 일관되게 적용한다.
- 수업 실습에 맞게 전체 구현을 단일 Python 파일로 제공한다.

### 범위에 포함

- pico2d 캔버스 생성과 스프라이트 이미지 로드
- 시트 안의 캐릭터 모션 및 프레임 범위 정의
- 프레임 순차 재생, 모션 반복 및 모션 간 대기
- 전체 모션 목록의 무한 순환 재생
- 창 종료 요청 처리

### 범위에 포함하지 않음

- 사용자 입력으로 모션을 선택하거나 재생을 제어하는 기능
- 속도, 크기, 순서를 조정하는 설정 UI
- 스프라이트 이미지 편집 또는 에셋 재배포
- 복수 파일로 나누는 모듈 구조

## 4. 사용자와 사용 흐름

사용자는 `Labs/LEC09`를 실행 위치로 하여 `sonic_animation_viewer.py`를 실행한다. 프로그램은 같은 폴더의 `sonic-sprite.png`를 읽고, 지정된 첫 모션부터 모든 모션을 순서대로 재생한다. 재생은 무한 반복되며, 사용자가 뷰어 창을 닫으면 프로그램이 종료된다.

## 5. 기능 요구사항

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-01 | 프로그램은 `sonic-sprite.png`를 읽어야 한다. | 필수 |
| FR-02 | 스프라이트 시트에 있는 모든 Sonic 애니메이션 모션을 빠짐없이 재생해야 한다. 제목, 크레딧, 장식 이미지 등 애니메이션 프레임이 아닌 요소는 모션으로 재생하지 않는다. | 필수 |
| FR-03 | 각 모션은 정의된 프레임 순서대로 재생해야 한다. | 필수 |
| FR-04 | 각 모션을 정확히 5회 완주한 뒤 다음 모션으로 이동해야 한다. | 필수 |
| FR-05 | 모션 재생이 끝날 때마다 1초 동안 대기한 뒤 다음 모션을 시작해야 한다. 마지막 모션 뒤에도 대기한 다음 첫 모션으로 돌아간다. | 필수 |
| FR-06 | 전체 모션 순서를 끝없이 순환 재생해야 한다. | 필수 |
| FR-07 | 각 프레임은 원본 프레임의 가로와 세로 크기를 각각 4배로 표시해야 한다. | 필수 |
| FR-08 | 창 닫기 요청을 처리하고 pico2d 리소스를 정상적으로 정리해야 한다. | 필수 |

## 6. 상세 동작 규칙

1. 모션 목록은 스프라이트 시트에서 확인한 순서대로 고정한다.
2. 한 번의 재생은 해당 모션의 모든 프레임을 처음부터 끝까지 한 번 표시하는 것을 뜻한다.
3. 모션별 재생 횟수는 5회이며, 재생 도중 다음 모션으로 건너뛰지 않는다.
4. 5회 재생이 끝난 후 1초를 대기한다. 마지막 모션이 끝난 뒤에도 같은 대기 시간을 적용한 다음 첫 모션을 시작한다.
5. 프레임 간격은 기본 0.1초로 한다. 이는 인접 수업 예제의 재생 간격을 따른다.
6. 프레임은 비율을 유지하고, 캔버스 안에서 잘리지 않도록 배치한다. 별도 연출이 없다면 캔버스 중앙에 표시한다.
7. 캔버스 크기는 4배 확대된 가장 큰 프레임이 잘리지 않도록 정한다.

## 7. 에셋 및 구현 기준

- 이미지 경로는 작업 디렉터리가 달라져도 찾을 수 있도록 스크립트 파일 위치를 기준으로 구성한다.
- 스프라이트 시트의 각 프레임은 필요한 원본 영역만 잘라 표시한다. 시트 전체를 단일 프레임으로 표시하지 않는다.
- 구현 전에 시트의 크기와 모션별 행/영역, 프레임별 시작 좌표 및 폭·높이를 확인한다.
- 모션과 프레임 정의는 순서를 보존하는 자료 구조로 관리하고, 모션별 프레임 수가 달라도 처리할 수 있어야 한다.
- 실행 코드는 `sonic_animation_viewer.py` 한 파일에 둔다. 추가 Python 모듈을 만들지 않는다.
- 외부 패키지 설치는 추가하지 않으며, 실행 환경에 pico2d가 설치되어 있다고 가정한다.

## 8. 비기능 요구사항

- Windows의 프로젝트 가상 환경에서 실행 가능해야 한다.
- 에셋 누락 또는 이미지 로드 실패 시 원인을 확인할 수 있는 오류를 제공해야 한다.
- 반복 재생 중 프레임 순서가 바뀌거나 모션이 누락되지 않아야 한다.
- 구현은 여러 단계로 나누어 진행하고, 전체 작업에서 의미 있는 커밋을 20회 이상 남긴다. 각 커밋은 작은 변경 단위로 구성하며, 실행할 수 없는 중간 상태가 오래 유지되지 않도록 한다.
- 커밋 메시지는 한국어로 작성한다.

## 9. 인수 기준

- [ ] `Labs/LEC09/sonic_animation_viewer.py` 단일 파일로 구현되어 있다.
- [ ] `sonic-sprite.png`를 스크립트 위치 기준으로 로드한다.
- [ ] 스프라이트의 모든 캐릭터 모션이 확인된 순서대로 포함되어 있고, 제목·크레딧 등의 장식 요소는 재생하지 않는다.
- [ ] 각 모션의 프레임이 지정된 순서로 재생된다.
- [ ] 각 모션이 정확히 5회 재생된 뒤 1초 대기한다.
- [ ] 마지막 모션 후 1초 대기하고 첫 모션부터 순환 재생한다.
- [ ] 표시되는 모든 프레임의 가로·세로 크기가 원본의 4배이고 캔버스에서 잘리지 않는다.
- [ ] 창 닫기 시 프로그램이 종료되고 리소스가 정리된다.
- [ ] 프로젝트 가상 환경에서 실행 확인을 마쳤다.
- [ ] 구현 변경 이력이 20회 이상의 의미 있는 커밋으로 구성되어 있다.

## 10. 개발 전 확인 사항

- `sonic-sprite.png`의 픽셀 크기와 투명 영역을 확인한다.
- 모든 캐릭터 모션 그룹의 이름, 시트 내 위치, 프레임 수를 목록으로 정리한다.
- 프레임별 잘라내기 좌표와 크기를 검증하고, 행 경계나 배경 픽셀이 프레임에 섞이지 않는지 확인한다.
- 4배 확대 후 가장 큰 프레임을 기준으로 캔버스 크기와 중앙 배치를 확인한다.

## 11. 검증 방법

- 정적 확인: 모션 목록과 프레임 좌표가 스프라이트 시트의 캐릭터 프레임 전체를 포함하는지 대조한다.
- 실행 확인: 가상 환경에서 프로그램을 실행해 각 모션, 5회 반복, 1초 간격, 무한 순환, 4배 표시를 눈으로 확인한다.
- 종료 확인: 재생 중 창을 닫아 정상 종료되는지 확인한다.
- 경로 확인: 프로젝트 루트와 `Labs/LEC09` 실행 위치 모두에서 이미지가 정상 로드되는지 확인한다.
